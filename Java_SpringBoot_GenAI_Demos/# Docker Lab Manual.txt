# Docker Lab Manual

## PART A: THEORY

### 1. What is Docker?

Docker is a **platform to build, ship, and run applications inside containers**.

An **application** = Code + Dependencies + Configuration

A **container** packages all of this together so it runs the same way anywhere.

---

### 2. Docker Architecture

```text
Docker Client
      |
      v
Docker Daemon (dockerd)
      |
   -----------------------------
   |        |        |         |
Images  Containers Networks  Volumes
      |
Docker Registry
```

---

### 3. Core Components

#### Docker Client

* The user interface for Docker.
* Examples: `docker build`, `docker run`, `docker ps`, `docker stop`
* When a user runs `docker run nginx`, the client sends the request to the Docker Daemon.

#### Docker Daemon (dockerd)

* The "brain" of Docker.
* Responsibilities: create containers, start/stop containers, build images, manage networks, manage volumes.

#### Docker Image

* The **blueprint** (like a Class).
* Example: `docker pull nginx` downloads the nginx image.

#### Docker Container

* A **running instance of an image** (like an Object).
* Example: `docker run nginx` → results in the nginx image running as an nginx container.

#### Docker Registry

* The image repository / storage location.
* Docker Hub → public registry
* AWS ECR → private registry
* Azure Container Registry → private registry
* Commands: `docker pull nginx`, `docker push myapp:v1`

#### Docker Volume

* Provides **persistent storage**.
* Problem: if a container is deleted, its data is lost.
* Solution: a volume stores data **outside** the container, so data survives container deletion.
* Examples: MySQL data, MongoDB data.

#### Docker Network

* The communication layer between containers.
* Example: Frontend container ↔ Backend container ↔ Database container — the network allows them to talk to each other.

### 5. Virtual Machine vs Docker Container

| Virtual Machine             | Docker Container          |
| --------------------------- | ------------------------- |
| Has a full Operating System | Shares the host OS kernel |
| Slower to start, heavier    | Fast startup, lightweight |
| More memory/CPU usage       | Less memory/CPU usage     |

**Benefits of Docker:** fast startup, less memory, less CPU, lightweight.

---

### 6. Volume vs No Volume — Why It Matters

|                                    | Without Volume                    | With Volume                                |
| ---------------------------------- | --------------------------------- | ------------------------------------------ |
| Where is data stored?              | Inside the container's filesystem | In a Docker volume (outside the container) |
| Container deleted (`docker rm -f`) | **Data is lost**                  | **Data is retained**                       |
| Container                          | Temporary                         | —                                          |
| Volume                             | —                                 | Persistent storage                         |

**Q1: Why use a Docker Volume?**

A: A volume provides persistent storage so data survives container deletion.

**Q2: Where is MySQL data stored?**

A: Without a volume → inside the container filesystem. With a volume → inside the Docker volume.

## Activity 3: Create a Docker Container

### How to create a container — step by step:

| Step | Description                                                                                | Command                                                          |
| ---- | ------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| 1    | Verify Docker is installed                                                                 | `docker --version`                                               |
| 2    | Check available images (you need an image before you can create a container)               | `docker images`                                                  |
| 3    | Create a container from an image — general syntax                                          | `docker run [OPTIONS] IMAGE_NAME`                                |
| 4    | Create and run a container (example: Spring Boot app), giving it a name and mapping a port | `docker run -d -p 8081:8081 --name springboot-app myapp:latest`  |
| 5    | Verify the container was created and is running                                            | `docker ps`                                                      |
| 6    | Access the application in a browser                                                        | `http://localhost:8081` (local) or `http://PUBLIC-IP:8081` (EC2) |

### Explanation of flags used above:

* `-d` → run in background (detached mode)
* `-p` → port mapping (host:container)
* `--name` → assign a name to the container

### `docker create` vs `docker run` (two ways to "create" a container):

| Command                                             | What it does                                                          |
| --------------------------------------------------- | --------------------------------------------------------------------- |
| `docker create --name myapp-container myapp:latest` | Creates the container but does **not** start it                       |
| `docker start myapp-container`                      | Starts the container created above                                    |
| `docker run --name myapp-container myapp:latest`    | Creates **and** starts the container in one step (most commonly used) |

### Example — Run MySQL image to create a MySQL container:

| Step | Description                                     | Command                                                                                                                                     |
| ---- | ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 3a   | Run the MySQL image to create a MySQL container | `docker run -d --name sb-mysql-db -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=mydb -e MYSQL_USER=myuser -e MYSQL_PASSWORD=root mysql:8.0` |

### Command breakdown:

* `docker run` → creates and starts a new MySQL container
* `-d` → runs the container in detached mode (in the background)
* `--name sb-mysql-db` → assigns the container the name `sb-mysql-db`
* `-e MYSQL_ROOT_PASSWORD=root` → sets the root password for MySQL (`root`)
* `-e MYSQL_DATABASE=mydb` → creates a database named `mydb`
* `-e MYSQL_USER=myuser` → creates a new user (`myuser`)
* `-e MYSQL_PASSWORD=root` → sets the password for `myuser` (`root`)

### Example — Nginx container:

```text
docker pull nginx:latest
docker run -d --name nginx-server -p 8080:80 nginx:latest
docker ps
```

### Container management commands:

| Action                | Command                               |
| --------------------- | ------------------------------------- |
| Start container       | `docker start springboot-app`         |
| Stop container        | `docker stop springboot-app`          |

## Activity 6: MySQL Container — Create Database and Table

| Step | Description                                   | Command                                                                                                                                  |
| ---- | --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | Pull the MySQL 8.0 image                      | `docker pull mysql:8.0`                                                                                                                  |
| 2    | Check available images                        | `docker images`                                                                                                                          |
| 3    | Run the MySQL image to create a container     | `docker run -d --name mysql-db -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=mydb -e MYSQL_USER=myuser -e MYSQL_PASSWORD=root mysql:8.0` |
| 4    | Verify the container is running               | `docker ps`                                                                                                                              |
| 5    | Access the MySQL database                     | `docker exec -it mysql-db mysql -u myuser -p`                                                                                            |
| 6    | List databases                                | `show databases;`                                                                                                                        |
| 7    | Switch to the database                        | `use mydb;`                                                                                                                              |
| 8    | Create the employee table                     | `create table employee(employeeId int, employeeName varchar(255), salary int);`                                                          |
| 9    | Insert data into the table                    | `insert into employee values(1001, 'John', 1000), (1002, 'jack', 2000);`                                                                 |
| 10   | View the records                              | `select * from employee;`                                                                                                                |
| —    | Exit the MySQL client                         | `exit;`                                                                                                                                  |
| 11   | Remove the MySQL container                    | `docker rm -f mysql-db`                                                                                                                  |
| 12   | Recreate the container using the same command | *(repeat step 3)*                                                                                                                        |
| 13   | Access the MySQL client again                 | `docker exec -it mysql-db mysql -u myuser -p`                                                                                            |
| 14   | List databases                                | `show databases;`                                                                                                                        |
| 15   | Switch to the database                        | `use mydb;`                                                                                                                              |
| 16   | List all tables                               | `show tables;`                                                                                                                           |

> **Note:** Without a volume, the table created in step 8 will **not** exist after step 11–12 (removing and recreating the container), since the data was stored only inside the deleted container. This is demonstrated in Activity 7.

## Activity 7: Create and Mount a Volume

| Step | Description                                                 | Command                                                                                                                                                               |
| ---- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | Create a Docker volume                                      | `docker volume create mysql-data`                                                                                                                                     |
| 2    | Stop/remove the existing MySQL container                    | `docker rm -f mysql-db`                                                                                                                                               |
| 3    | Run a MySQL container attached to the volume                | `docker run -d --name mysql-db -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=mydb -e MYSQL_USER=myuser -e MYSQL_PASSWORD=root -v mysql-data:/var/lib/mysql mysql:8.0` |
| 4    | Verify the volume is mounted correctly                      | `docker inspect mysql-db`                                                                                                                                             |
| 5    | Access the MySQL client to add data                         | `docker exec -it mysql-db mysql -u myuser -p`                                                                                                                         |
| 6    | List databases                                              | `show databases;`                                                                                                                                                     |
| 7    | Switch to the database                                      | `use mydb;`                                                                                                                                                           |
| 8    | Create the employee table                                   | `create table employee(employeeId int, employeeName varchar(255), salary int);`                                                                                       |
| 9    | Insert data into the table                                  | `insert into employee values(1001, 'John', 1000), (1002, 'jack', 2000);`                                                                                              |
| 10   | View the records                                            | `select * from employee;`                                                                                                                                             |
| 11   | Remove the MySQL container                                  | `docker rm -f mysql-db`                                                                                                                                               |
| 12   | Recreate the container using the same command (same volume) | *(repeat step 3)*                                                                                                                                                     |
| 13   | Access the MySQL client inside the container                | `docker exec -it mysql-db mysql -u myuser -p`                                                                                                                         |
| 14   | List databases                                              | `show databases;`                                                                                                                                                     |
| 15   | Switch to the database                                      | `use mydb;`                                                                                                                                                           |
| 16   | List all tables                                             | `show tables;`                                                                                                                                                        |
| 17   | Select data from the employee table                         | `select * from employee;`                                                                                                                                             |

> **Result:** Because the volume `mysql-data` is mounted at `/var/lib/mysql`, the `employee` table and its data **survive** container removal and recreation — unlike Activity 6.

## Spring Boot Volume Example

|                | Command                                                                       | Result                                           |
| -------------- | ----------------------------------------------------------------------------- | ------------------------------------------------ |
| Without volume | `docker run -d --name app -p 8081:8081 myapp:latest`                          | Uploaded files are lost after container deletion |
| With volume    | `docker run -d --name app -p 8081:8081 -v app-data:/app/uploads myapp:latest` | Uploaded files remain safe                       |
